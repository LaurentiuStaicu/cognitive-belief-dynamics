# How to use CEM without confusing the map with the territory

## Central idea

CEM is most useful when explanation comes before optimization:

Understand → explore the mechanism → inspect evidence → compare factors → plan action.

[[VIEW:learning]] · [[VIEW:reference]] · [[VIEW:planning]] · [[VIEW:process]]

## 1. Understand

Start in Theory. Chapters 0–4 explain the architecture and conceptual boundaries. Chapters 5–10 describe executable mechanisms and their evidence. Chapters 11–13 cover future mechanisms and the interpretive layer. Chapter 14 explains validation.

When you encounter an interactive term, select it. The inspector should answer three questions: what does it mean, what is its epistemic status, and where can it be seen in the model?

## 2. Explore the mechanism

Use [[VIEW:learning]] for mechanisms and scenarios. Always follow intermediate variables. If an outcome changes, ask which state changed first and by what rule.

Open [[VIEW:process]] for the full process. Visual ODD shows event ordering and the separation between environment, agent states and observations.

## 3. Inspect the evidence

Open [[VIEW:reference]]. Check whether a source is MODEL_EVIDENCE, BACKGROUND_THEORY or INTERPRETIVE_SOURCE. A citation near a chapter does not automatically validate an executable equation.

Also inspect “what it is not” for each variable. These boundaries are part of the model, not decorative notes.

## 4. Compare factors and scenarios

Use published scenarios to see how one controlled change alters a trajectory. Compare nested models where available. Do not interpret demonstrative differences as population effect sizes.

## 5. Plan action

Only then open [[VIEW:planning]]. Select objective, budget and effort costs, and inspect why one bundle ranks above another. Examine leave-one-out effects, nonadditivity and sensitivity profiles.

The result is a priority inside the model, not an automatic policy recommendation.

## Control question

On every screen ask: “Am I looking at an empirical fact, an executable implementation, a conceptual hypothesis or an interpretation?” If the answer is unclear, return to Registry and Theory.

## What this chapter does not claim

Using the application correctly does not remove scientific uncertainty. CEM is a tool for explaining and testing candidate mechanisms; its value increases when limitations are as inspectable as results.
