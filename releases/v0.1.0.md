# Cognitive Belief Dynamics v0.1.0

**Scientific-core baseline — initial research release**

Cognitive Belief Dynamics (CBD) v0.1.0 is the first formal public snapshot of the repository after consolidation around the scientific model core.

## What this release contains

- the canonical CBD model specification and registries;
- the Python computational/reference implementation;
- JSON schemas and explicit model/evidence contracts;
- empirical-target and evidence metadata;
- calibration and retained synthetic model-recovery benchmark artifacts;
- integrity and provenance artifacts associated with retained results;
- scripts directly required to reproduce the scientific-core results.

The previous end-user/frontend product layer is intentionally not part of this release.

## Scientific status

This is a **research release in initial development**. The version number identifies a frozen repository artifact; it is not a claim that the complete model is empirically validated.

MOD.14 includes a normative proposition-level Bayesian reference update and an explicit uncertainty calculation. It is a reference computation, not a population-calibrated model, not a claim that the brain literally implements Bayes' rule, and not a truth oracle.

M1.E4 has retained synthetic model-recovery and protocol-robustness results. In the participant-aware confirmation benchmark, all 18 primary P64_X10 cells meet the declared 0.80 recovery gate, with a minimum observed recovery of 0.92. These results concern synthetic identifiability/discrimination only. They do not establish EVSD or 2HT as the true human recognition architecture, identify Pencode, or constitute human validation.

## Explicit limitations

v0.1.0 does not establish:

- population calibration of the full model;
- human-participant validation of M1.E4;
- identification or estimation of Pencode;
- authorization of participant recruitment;
- a general-purpose truth, prediction, diagnostic, or decision system;
- a production-ready end-user application.

See `STATUS.md` for the maintained scientific boundary and `CITATION.cff` for citation metadata.

## Versioning

The project uses Semantic Versioning for repository/software artifacts. The `0.x.y` series denotes initial development. Scientific validation status is documented separately and must not be inferred from the version number alone.
