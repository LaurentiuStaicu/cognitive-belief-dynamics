# Alpha 0.4.3a0 — Optimization & Visual Polish Consolidation

Alpha 0.4.3a0 consolidates the completed web Optimization Architecture track through OA-8 and the VP-0 through VP-4 Visual Polish implementation. It is a product-architecture, trust, accessibility and presentation release over the existing active M1 candidate specification; it does **not** activate a new scientific mechanism.

## Optimization Architecture

The Optimization Architecture turns the browser application from a collection of model views into a coherent, local-first epistemic workbench while preserving the scientific baseline.

- **OA-0 — Architecture contract and baseline:** establishes the integrated optimization contract, semantic/quality invariants and the rule that optimization work cannot silently change scientific outputs.
- **OA-1 — Semantic Spine:** adds canonical semantic entities, relations, stable identifiers, epistemic statuses and web consumers so the same concept can be traced consistently across surfaces.
- **OA-2 — Workspace + Provenance:** adds versioned local workspaces, transactional persistence/migration/recovery and provenance-bearing analyses without requiring a remote account.
- **OA-3 — Information Architecture + Visual Language:** organizes the application around **Understand / Analyze / Act / Library** and establishes the quiet-scientific visual contract, responsive layout and bilingual presentation rules.
- **OA-4 — Universal Inspector + Search:** adds semantic search, canonical inspection, cross-links and keyboard-first deep linking without exposing internal retrieval scores as meaning.
- **OA-5 — Active Understanding:** introduces the Predict → Reveal → Explain → Boundary learning flow and model-challenge paths while keeping learning state separate from scientific state.
- **OA-6 — Decision Under Uncertainty:** decomposes assumptions and uncertainty, adds conditional robustness/sensitivity and research-priority reasoning, and explicitly prevents scenario frequency from being presented as real-world probability or a simulation ranking as a recommendation.
- **OA-7 — Reality Loop:** separates SimulationResult, DecisionAnalysis, ImplementationPlan and ObservedOutcome; adds Action Canvas, indicator/trigger objects, persisted observations, read-only trigger evaluation and decision-autopsy/revision trails. Observations cannot rewrite prospective plans, and no automatic real-world action is executed.
- **OA-8 — Trust Hardening:** consolidates WCAG-oriented browser gates, keyboard/reflow checks, import hardening, Dependency Review, CodeQL, performance budgets, SPDX SBOM generation and release provenance.

The previously described **OA-9 native elementary OS / Flatpak work is intentionally deferred** until the web product has all planned modules and is close to version 1.0. The native application remains a later official variant sharing the same scientific and semantic artifacts; it is not developed in parallel during the current module-completion phase.

## Visual Polish

Visual Polish reduces visual friction without weakening or hiding epistemic boundaries.

- **VP-0 — visual contract/baseline:** freezes the scope and regression expectations for polish work.
- **VP-1 — Typography, Surfaces & Spacing:** establishes a calmer system-first type hierarchy, 6 px spacing rhythm, restrained reading measure and consistent raised/inset surfaces.
- **VP-2 — Navigation, Controls & Interaction States:** unifies target sizes, hover/active/disabled/focus treatment and ensures selected states retain non-color cues.
- **VP-3 — Charts & Data-Dense Surfaces:** standardizes chart/table containers, sticky dense-table headers, tabular numerals and exact-value alternatives; narrative series use solid/dashed/dotted patterns so meaning is not carried by color alone.
- **VP-4 — Responsive / Cross-View Visual Closure:** adds an authoritative Playwright matrix covering all seven top-level views at 320 CSS px in light and dark modes and again at 200% root text, with diagnostics for document-level horizontal overflow.
- **VP-5 — release closure:** synchronizes version metadata and deterministic exports, records the cumulative OA+VP change set and verifies the public release/deployment path.

## Scientific boundary

The active model specification remains **M1**, retaining **M0** as the explicit baseline. The evidence snapshot remains `EVIDENCE.M1.2026-09-16.r1`.

This consolidation release does not:

- change M0 equations or saved M0 reference trajectories;
- change the scientific outputs of M1.E1, M1.E2 or M1.E3;
- calibrate demonstrative coefficients to a population;
- activate M1.E4, `Pencode`, EVSD or 2HT as a human cognitive mechanism;
- turn scenario coverage into probability;
- turn user-declared planning thresholds into validated cutoffs;
- turn software/reproducibility validation into psychological or population validation;
- turn simulation rankings into real-world recommendations.

Research documents already carrying the `ALPHA_0.4.3a0_*` prefix remain research/protocol artifacts unless separately activated through a scientific gate. This release identifier therefore records the software consolidation milestone, not an implicit promotion of those candidate mechanisms.
