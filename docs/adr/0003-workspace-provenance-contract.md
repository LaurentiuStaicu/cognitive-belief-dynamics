# ADR 0003 — OA-2 workspace and provenance contract

Status: Accepted for OA-2A implementation.

## Context

OA-1 established the Semantic Spine so stable scientific identity is available to
web consumers. Workspace persistence must therefore reference canonical semantic
IDs rather than copying labels, prose, graph objects or view-local structures.

The agreed OA-2 scope is case/workspace persistence with separate software/model/
evidence versions, autosave, undo/redo, recovery snapshots, .cem.json export/import,
schema migration and minimal provenance.

W3C PROV is used only as a conceptual mapping target: workspace revisions are
entities; save/import/migrate/recover operations are activities; activities use
existing entities and generate new revisions; revision ancestry is explicit.
CEM does not adopt RDF or PROV-O as its native storage format.

## Decision

OA-2 uses a versioned JSON workspace document validated by JSON Schema Draft
2020-12.

The v1 contract has these invariants:

1. scientific objects are referenced by stable IDs from the Semantic Spine;
2. user-authored title/notes are allowed, but canonical scientific labels or objects
   are not copied into workspace state;
3. software version, model specification, evidence snapshot, semantic schema version
   and semantic baseline contract remain separate fields;
4. provenance records explicit activities, used references, generated workspace
   revisions and optional revision ancestry;
5. validation never migrates or rewrites a document in place;
6. an unknown future schema version fails closed;
7. the current workspace revision must have been generated by recorded provenance;
8. OA-2 changes no model equation, coefficient, evidence status or reference output.

## Implementation slices

### OA-2A — contract and validator

- workspace JSON Schema;
- canonical fixture;
- semantic-reference integrity validation;
- minimal provenance/revision invariants;
- regression tests.

No UI or persistence behavior.

### OA-2B — local persistence and recovery

- local workspace store;
- autosave;
- undo/redo snapshots;
- crash/recovery snapshot;
- save→close→load identity tests.

### OA-2C — portable files and migration

- export/import .cem.json;
- explicit schema migration pipeline;
- original imported document preserved;
- old-schema migration preserves semantics;
- corrupted files rejected safely;
- unknown future schema never destructively migrated.

## Deferred

OA-3 owns information architecture/visual language.
OA-4 owns Universal Inspector and Search.
Later OA stages retain their previously defined scopes; OA-2 does not pull them
forward.

## Consequences

Workspace state becomes portable and auditable without becoming a second scientific
registry. Later UI surfaces can pin, save and inspect canonical entities while
provenance remains distinct from scientific/evidence relations.
