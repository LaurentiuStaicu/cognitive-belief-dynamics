# Alpha 0.4.3a0 — Optimization & Visual Polish closure audit

Status: VP-5 release gate.

Date: 2026-09-17.

## Scope

This audit closes the web Optimization Architecture implementation through OA-8 and Visual Polish through VP-4, then prepares software release `0.4.3a0` / tag `v0.4.3a0`.

It is not a scientific-model activation gate. M1.E4 and later candidate-mechanism research remain outside this release unless separately approved through the scientific track.

## Authoritative retained scientific baseline

- active model specification: `M1`;
- retained baseline: `M0`;
- evidence snapshot: `EVIDENCE.M1.2026-09-16.r1`;
- active executable M1 comparators retained from the prior public release: M1.E1, M1.E2 and M1.E3;
- no calibration or population interpretation is introduced by OA or VP work.

The OA architecture contract forbids optimization work from changing M0 trajectories, M1.E1–E3 outputs, activating M1.E4/Pencode/EVSD/2HT, converting synthetic steps into empirical time, converting software validation into psychological validation, or converting rankings into recommendations.

The completed web critical path is OA-0 through OA-8:

## VP closure

- VP-0 established the visual baseline and scope guard.
- VP-1 refined typography, surfaces and spacing.

The exact VP-5 PR head must pass:

## Merge is also publication authorization

The release workflow is chained from a successful main-branch verification run. Therefore merging the VP-5 PR is not merely a code integration step: after post-merge Verify succeeds it is expected to trigger creation of the new prerelease `v0.4.3a0` and deployment of the verified web artifact.

For that reason VP-5 must stop at an explicit GO before merge.

## Post-merge/publication closure

VP-5 is complete only when all of the following are confirmed from GitHub:

- post-merge Verify on the exact main SHA = success;
- post-merge CodeQL = success;
- GitHub prerelease `v0.4.3a0` exists and is published;
- release notes visibly distinguish Optimization Architecture from Visual Polish;
- release assets/checksums/SBOM/provenance are present as configured;
- GitHub Pages deployment from the verified artifact = success;
- the public app exposes the new version/tag correctly.

Only then may the project return to the M1 Definition of Done and M1 completion track.
